# Model Description — Subject-level EEG Alzheimer’s Classifier

This document describes what the training script `train_ml_model.py` does, including **inputs**, **processing**, and **outputs**.

---

## What problem the model solves

The implemented model is a **lightweight machine-learning classifier** that predicts whether an EEG subject is:

- **HC**: Healthy Control
- **AD**: Alzheimer’s Disease

By default, it trains/evaluates **binary HC vs AD** (FTD is excluded from training/evaluation).

---

## Inputs

`train_ml_model.py` is designed to plug into the project’s already-generated feature pipeline outputs.

### Required files

- **`eeg_subject_features.npy`**
  - **Type**: NumPy array, `float`
  - **Shape**: `(n_subjects, 19, 4)`
  - **Meaning**:
    - 19 EEG channels
    - 4 frequency-band power features per channel:
      - Delta, Theta, Alpha, Beta

- **`eeg_subject_groups.npy`**
  - **Type**: NumPy array, `str`
  - **Shape**: `(n_subjects,)`
  - **Values**: `'HC'`, `'AD'`, `'FTD'`
  - **Meaning**: subject diagnosis group aligned by index with `eeg_subject_features.npy`

### Where these inputs come from

These arrays are generated by the feature extraction pipeline (Welch PSD → band powers) implemented in `eeg_frequency_band_analysis.ipynb` and referenced in the project proposal.

---

## Feature representation (what the model “sees”)

Each subject starts as a `(19, 4)` feature grid:

- **19 channels × 4 band-power values**

The script flattens this into a single vector per subject:

- **76 features per subject** ( \(19 \times 4 = 76\) )

Before training, the feature matrix is sanitized to avoid numeric issues:

- Any `NaN`, `+inf`, or `-inf` values are replaced with **0.0**

---

## Labels

For the default task (`--task hc_vs_ad`):

- `y = 1` for **AD**
- `y = 0` for **HC**
- **FTD subjects are excluded**

This matches the “subject-level” modeling requirement in the proposal and prevents epoch-level leakage.

---

## Models implemented

The script supports two lightweight baseline models:

- **Logistic Regression** (`--model logreg`)
  - Uses class balancing (`class_weight="balanced"`)
  - Applies a `log1p` transform to stabilize the band-power dynamic range
  - Standardizes features (`StandardScaler`)

- **Random Forest** (`--model rf`)
  - Uses class balancing (`class_weight="balanced"`)
  - Nonlinear tree-based baseline (still lightweight and interpretable)

---

## Evaluation (how performance is measured)

The script evaluates using **subject-level Stratified K-Fold cross-validation**, which means:

- Each subject appears in **exactly one** fold’s validation split
- Class proportions (HC vs AD) are preserved per fold (stratified)

### Reported metrics

The script prints and saves:

- **Accuracy**
- **ROC-AUC**
- **Sensitivity** (AD recall)
- **Specificity** (HC recall)
- **Confusion matrix** (positive class = AD)

---

## Outputs

After running, the script creates an `artifacts/` directory (configurable) containing:

### 1) Metrics JSON

- Path pattern: `artifacts/metrics_<task>_<model>_<timestamp>.json`
- Contains:
  - run parameters (folds, seed, number of features, etc.)
  - all evaluation metrics

### 2) Saved fitted model

- Path pattern: `artifacts/model_<task>_<model>_<timestamp>.joblib`
- A fitted scikit-learn pipeline you can reload later to run predictions.

---

## How to run

From the repository root:

```bash
# Logistic regression baseline (recommended first)
python3 train_ml_model.py --model logreg

# Random forest baseline
python3 train_ml_model.py --model rf
```

If your environment blocks multiprocessing, keep CV single-process (default):

```bash
python3 train_ml_model.py --model logreg --n-jobs 1
```

---

## What to do with the saved model

Once you have a `.joblib` file, you can load it and run predictions on feature vectors with the same 76-feature format:

- Input for prediction: `X_flat` with shape `(n_subjects, 76)`
- Outputs:
  - `predict_proba(X_flat)[:, 1]` → probability of **AD**
  - `predict(X_flat)` → predicted class (0=HC, 1=AD)
